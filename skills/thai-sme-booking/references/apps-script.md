# Apps Script backend

A container-bound script on the shop's Google Sheet. Files are global-scope scripts (no modules); `Lib.js` is pure logic shared with the Node tests. Nothing else may reference another file at top level. Wrap cross-file access in functions, because load order is not guaranteed.

## Files
| File | Role |
|---|---|
| `Code.js` | `doPost` router (checks `SHARED_SECRET`), webhook event loop with redelivery dedupe (CacheService, 6 h) |
| `Sheet.js` | Tab schema (`TABS`), defaults, row read/write, typed readers, `cell_()` keeps phone/ID/time strings as text |
| `Booking.js` | `createBooking_` (lock, one hold per user, slot re-check), `onConfirmed_`, installable `onSheetEdit` |
| `Slots.js` | Availability = hours − holidays − blocking bookings − owner calendar events |
| `Slip.js` | Image → provider adapter → `Lib.validateSlip` → confirm or NEEDS_REVIEW; `SLIP_PROVIDERS` |
| `Faq.js` | FAQ/booking-intent replies, placeholders, `/owner` registration, **`handleUnmatched` extension point** |
| `Line.js` | Reply/push/content/loading/quota APIs, owner alerts |
| `Messages.js` | Thai strings + Flex bubbles (booking button, confirmation, reminder) |
| `Calendar.js` | Create/delete events (tagged `bookingRef`), read blocking events |
| `Reminders.js` | Triggers: `sendReminders` (daily), `expireHolds` (10 min), `purgeOldData` (monthly) |
| `Site.js` | `siteData_` (whitelisted public settings only) and the `publishSite` menu |
| `Setup.js` | Menu, `setup()` (tabs, seed, formatting, triggers, owner code), `monthlyReport`, quota, test alert |
| `Seed.js` | Generated from client.yaml; fills empty tabs once |

## Deploy
```
cd clients/<slug>/build/apps-script
npx @google/clasp login
npx @google/clasp create-script --type sheets --title "<shop> ระบบจอง" --rootDir .
node <kit>/scripts/build-config.mjs clients/<slug>/client.yaml   # restores appsscript.json (create-script overwrites it)
npx @google/clasp push -f
```
**Gotcha:** `create-script` downloads Google's default manifest over ours: timezone `America/New_York`, no `webapp` block, no scopes. Always restore it before the first push. `setup()` shows a ⛔ warning if the script timezone isn't Asia/Bangkok.
- Script Properties (⚙️ Project Settings): `SHARED_SECRET`, `LINE_CHANNEL_ACCESS_TOKEN`, `SLIP_PROVIDER` (`easyslip`), `SLIP_API_KEY`, `PAGES_DEPLOY_HOOK`. Optional: `SLIP_API_URL`, `SLIP_FILE_FIELD` (see payments-slip.md). `OWNER_SETUP_CODE` is generated by setup.
- In the Sheet: menu 🗓️ ระบบจอง → ⚙️ ติดตั้ง / ซ่อมระบบ. It is safe to re-run: it creates missing tabs, seeds only empty tabs, and re-installs triggers.
- **Web app**: `npx @google/clasp create-deployment -d "v1"` (it uses the manifest's `webapp` block: execute as the deploying user, anyone can call). URL = `https://script.google.com/macros/s/<deploymentId>/exec` → Worker `GAS_URL`. The UI way is Deploy → New deployment → Web app.
- **After every code change**: `clasp push -f && clasp update-deployment <deploymentId>` (or UI: Deploy → Manage deployments → ✏️ → New version). The `/exec` URL stays the same. Forgetting this step is the #1 "my fix didn't work" cause.

## Sheet conventions (owner-facing)
- `Bookings.status` is a dropdown: PENDING_DEPOSIT, CONFIRMED, NEEDS_REVIEW, EXPIRED, CANCELLED, COMPLETED, NO_SHOW (color-coded).
  - NEEDS_REVIEW → CONFIRMED: sets `paid_at`, creates the calendar event, pushes the confirmation to the customer.
  - → CANCELLED: deletes the calendar event.
  - COMPLETED / NO_SHOW: optional, used for the no-show rate in reports.
- Hours: `day` accepts `mon…sun` or Thai names. Times are typed as text `10:00`. `closed` is a checkbox or `ปิด`.
- Services: `deposit` blank = shop rule, `0` = no deposit, number = fixed. `active` FALSE hides a service.
- Settings: key/value with Thai notes. Never put secrets here, because the Sheet is shared with the owner.

## Quotas (consumer Gmail, per day, approximate)
URL Fetch 20,000 · triggers total runtime 90 min · script runtime 6 min per execution · email 100 recipients. A single shop uses a tiny fraction. The busiest path is `expireHolds` every 10 minutes (reads one sheet).

## Why these design choices
- **LockService around booking creation** prevents two customers taking the last slot at the same moment.
- **One pending hold per LINE user** stops a single customer from hoarding slots.
- **Expired holds can still be paid**: a slip for an EXPIRED booking (within 24 h) confirms it if the slot is still free, otherwise it goes to review.
- **Anonymize, don't delete** (`purgeOldData`): keeps revenue stats while removing name, phone and userId after `retention_months`.
